# Сохранение статической копии

1. Прочитать `AGENTS.md`, `migration/PLAN.md`, `migration/INVENTORY.md`, `migration/STATUS.md`, `migration/DESIGN.md`, `migration/CONTENT_PARITY.md` и реестры. Прочитать готовый `../frontend-design/SKILL.md` с проектными ограничениями. Реализация разрешена только после нового поручения начать перенос. Если инвентаризация не выполнена, сначала использовать `../ufalit-inventory/SKILL.md`.
2. Использовать готовый инструмент скачивания и браузер. Не писать собственную программу переноса и не просить пользователя разрабатывать сайт. Сохранять именно полные HTTP-ответы и файлы; краткий веб-текст и скриншоты не заменяют HTML и оригиналы медиа.
3. Сначала выполнить пилот из плана. Сохранять исходные загрузки временно вне `site/`; готовый результат — в `site/`. Проверить схему путей и кодировку до массовой обработки. Если инструмент не может скачать полноценные данные, записать блокировку, не подменять их пересказом.
4. Для каждой страницы сохранить всё основное содержание в новой современной вёрстке по DESIGN.md: заголовки, абзацы, стихотворные строки, таблицы, библиографию, подписи, ссылки, изображения и именованные якоря. Не обрезать длинные статьи. Сохранить датированное контрольное извлечение текста источника в evidence; записать соответствия блоков в content-parity.csv. Старую компоновку и CSS-шаблон не копировать.
5. Для каждого файла проверить фактический ответ, MIME и размер. Не принимать HTML ошибки/заглушки за изображение или PDF. Скачать оригиналы галереи, а не только миниатюры; сохранить привязку к категории, порядок, подпись и переход к полному изображению.
6. Выбрать читаемые стабильные локальные пути без query в имени; учесть регистр, Unicode, URL-кодирование и коллизии одинаковых имён. При дедупликации по SHA-256 сохранить происхождение всех URL. Хранить оригиналы без потери качества; разрешены адаптивные производные для srcset с доказанной связью с оригиналом по CONTENT_PARITY.md.
7. Переписать внутренние ссылки по `pages.csv`, ресурсы — по `assets.csv`. Ссылки на фрагменты сохранить. Проверить `srcset`, фоновые картинки, CSS-импорты, шрифты, ссылки внутри CSS и пути, встроенные в старые скрипты. Убрать зависимость от `<base>` исходного домена.
8. Сайт должен работать по адресу проекта `/ufalit/` и на вложенных страницах. Не оставлять корневые `/images/...`, которые ведут в корень аккаунта вместо проекта, и не хранить абсолютные локальные пути компьютера.
9. Не переносить PHP как исполняемую часть. Чистые статические ссылки должны вести на HTML. Старый JS не копировать автоматически. Для фотоподборок делать современную адаптивную галерею или уместную карусель по DESIGN.md, сохранив все изображения, порядок, подписи и оригиналы. Предпочитать нативный HTML/CSS и готовые лёгкие компоненты с минимальным JS. Не разрабатывать новый проигрыватель, карту или поиск.
10. Проверить формы, поиск, печать, вход/выход, галереи, карту и видео по матрице возможностей. Серверные кнопки заменить понятной статической навигацией или явно описать ограничение в exceptions и интерфейсе. Не оставлять вводящую в заблуждение работающую на вид форму. Существенную потерю функции вынести пользователю с конкретным вариантом решения.
11. Внешним видео/картам сохранить название, подпись, источник и пригодное штатное встраивание; отдельно учесть зависимость. Каждое видео сверить по ID/источнику и реальному воспроизведению. Ссылка или постер вместо работающего видео — ограничение, а не успешный перенос; зафиксировать по CONTENT_PARITY.md. Локальные аудио/видео скачивать как файлы, если укладываются в согласованный охват и лимиты. Крупные файлы не пропускать молча.
12. Только после наличия файлов отмечать `captured`, заполнять размеры, хеши и evidence. Выполнить проверку партии по `../ufalit-verify-release/SKILL.md`; `verified` назначать только проверенным позициям. Обновить STATUS.md, коммитить законченную партию и проверить её на GitHub.

Не создавать CNAME, деплой или ветку публикации на этапе переноса. Итог партии: полные файлы в `site/`, обновлённая карта URL и ресурсов, поэлементная матрица текста/картинок/видео, доказательства сравнения, явные исключения и следующая очередь.
