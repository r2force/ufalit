# Уфа литературная — статическая копия

Сайт опубликован: **https://r2force.github.io/ufalit/**

Перенос с [исходного сайта](https://ufalit.ufacsdb.ru/) завершён. История работ, отчёты и исходные ссылки сохранены в архиве проекта.

GitHub Actions собирает страницы из `site/` и общих шаблонов. Публикация собранного каталога `site/` запускается вручную в [workflow Pages](.github/workflows/pages.yml) с параметром `deploy`. Прежняя ветка `gh-pages` сохранена как история первой публикации.

Общий каркас, шапка, меню, хлебные крошки и футер редактируются в [templates/](templates/). В начале каждого исходного HTML между строками `---` записаны параметры страницы в JSON. Поле `title` задаёт заголовок вкладки, `breadcrumbs` — последовательность подписей и ссылок, `styles` и `scripts` — дополнительные файлы из `site/assets/` (скрипты и стили справочника, читального зала, просмотра иллюстраций, аудиостудии и библиографии подключаются автоматически по разметке и параметрам). После параметров идёт HTML основного материала. На главной метка `<!-- main -->` отделяет вступление перед основным содержанием, параметр `atlas` включает карту на месте `<!-- atlas -->`, а массив `guide_cards` заполняет карточки разделов.

Карта использует адаптированный виджет из `design_example/ufamap/`. Единственный источник её мест, координат, фотографий и описаний — [atlas-places.json](templates/atlas-places.json); сборщик формирует из него список ссылок, начальную карточку и JSON для браузера. Оформление карты — `site/assets/atlas.css`, логика главной — `site/assets/ufalit-map.js`, общий виджет — `site/assets/map-widget.js`. Поиск и фильтры работают и при недоступной подложке. Библиотека MapLibre GL JS 6.19.0, её CSS, worker и лицензия находятся в `site/assets/vendor/maplibre-gl/`; картографическая подложка и шрифты подписей загружаются с OpenFreeMap. Атрибуция поставщиков сохранена на карте. Проверка: `node scripts/test_home_map.js`.

Порядок добавления и исправления меток, описание полей, категории фильтров и проверки собраны в [инструкции по меткам карты](AGENTS.md#метки-литературной-карты).

Координаты демонстрационного сада исправлены по [географической привязке сада Аксакова](https://ru.wikipedia.org/wiki/Сад_Аксакова); для музея Гафури использован [адресный справочник](https://ufa.spravka-region.ru/tags/muzei/Memorialnyj-dom-muzej-M-Gafuri-3), для библиотеки — [привязка здания на ул. Мингажева, 109](https://bashkortostan.spravochnika.ru/c-ufa/biblioteki). Точка улицы Мустая Карима обозначает её центральный участок, а не отдельное учреждение. Тексты и архивные фотографии сохранены из прежней карты и раздела памятных мест.

В фотоальбомах поле `heading` задаёт заголовок альбома, а список `photos` хранит снимки в порядке показа. Если в теле страницы нет явной метки `<!-- photos -->`, сборка формирует альбом по [шаблону фотоальбома](templates/gallery-album.html) и вставляет карточки по [шаблону фотографии](templates/photo.html). Обычная подпись хранится в `caption`, подпись с разметкой — в `caption_html`; для отдельного описания изображения используется `alt`. Снимки загружаются с `loading="lazy"`; для исключений укажите `"loading": "eager"` либо `"loading": null` (пропустить атрибут). Метка `<!-- photo-count -->` выводит число снимков с русским склонением. В статьях иллюстрации внутри `.material-figure`, `.material-inline` и `.legend-figure` записываются как обычные `<img>` и при сборке автоматически оборачиваются ссылкой на оригинал по [шаблону иллюстрации](templates/zoom-image.html).

В каталогах у ссылки на альбом укажите `data-cover` с путём к обложке либо `data-writer` с ключом писателя из [writers.json](templates/writers.json) — сборка подставит портрет, имя и адрес раздела. В справочниках (`personalities`, `places`, `awards`) шапка формируется по `heading` и `intro` через [шаблон баннера](templates/directory-banner.html). На страницах с аудио объект `audio_studio` формирует [аудиостудию](templates/audio-studio.html), а массив `tracks` (`id`, `title`, `src`) на месте `<!-- tracks -->` выводит дорожки по [шаблону аудиозаписи](templates/audio-track.html). На видеостраницах поле `heading` и массив `videos` (`title`, `src`, при необходимости `id` и `description`) формируют страницу по [шаблону видеоподборки](templates/video-album.html) и выводят карточки по [шаблону видеозаписи](templates/video.html). GitHub Actions собирает готовые HTML перед публикацией.

«Видеокопилка» оформляется отдельными шаблонами `templates/archive-*.html`, стилями `site/assets/video-archive.css` и скриптом `site/assets/ufalit-video.js`. Поле `video_archive` на странице коллекции ссылается на писателя из `writers.json`; список `video_collections` на странице каталога задаёт порядок коллекций. Имена, портреты и количество записей подставляются из этих источников при сборке. Названия и MP4-ссылки остаются в исходных массивах `videos`. На странице коллекции один нативный плеер: выбор превью запускает запись и обновляет заголовок, заставку и ссылку скачивания. Без JavaScript плеер показывает первую запись, остальные ссылки открывают исходные MP4. Превью в `site/assets/video-archive/previews/<коллекция>/<имя MP4>.jpg` содержат настоящие кадры соответствующих роликов, размер — не более 640×360 пикселей; это небольшие обычные Git-файлы, исключённые из LFS. При добавлении записи добавьте её превью с тем же именем файла. Банки на витрине содержат портрет, имя писателя и количество записей на одной этикетке.

Проверка видеокопилки: `python3 scripts/test_video_archive.py` (один плеер, все 25 записей, превью и ссылки скачивания).

Читальный зал состоит из каталога литераторов, страниц `reading-author-<ключ>` со списком материалов и страниц отдельных произведений. В `templates/reading-room.json` массив `works` задаёт единственный список материалов, а `groups` — их подборки и общие пояснения `notes_html`, которые выводятся под заголовком «Произведения и материалы». Поле `group` связывает произведение с подборкой; `author` при необходимости уточняет автора отзыва или посвящения. Каждая аудиостраница содержит одну дорожку. Старые адреса подборок с метаданными `reading_group` показывают ссылки на новые страницы; `legacy_anchor` сохраняет номера аудиодорожек. Портреты и сведения об авторах берутся из `templates/writers.json`. Общие шаблоны `reading-*.html`, стили `reading-room.css` и `ufalit-library.js` отвечают за витрину и полки.

При сборке в каталог встраивается полнотекстовый индекс всех отдельных материалов: текст страниц и названия аудиодорожек. `ufalit-search.js` ищет целые слова, поддерживает точные фразы в кавычках и равнозначные «е/ё», ранжирует совпадения и формирует фрагменты с подсветкой. Короткие служебные слова не подсвечиваются внутри многословного запроса; цельная найденная фраза подсвечивается целиком. Запрос сохраняется в параметре `q`; ссылки из результатов используют текстовые фрагменты браузера для перехода к совпадению. Индекс обновляется автоматически при изменении материалов. Проверка поиска на настоящем корпусе: `node scripts/test_reading_search.js`.

`ufalit-reader.js` добавляет темы, размер текста, режим «Только текст», прогресс и сохранение позиции в этом браузере. Старые ссылки `reading/#read-<ключ>` открывают полку автора. Проверка охвата каталога, переходов, авторства, сохранности исходных абзацев, иллюстраций и всех записей: `python3 scripts/test_reading_room.py`. Контрольные суммы и решения по границам произведений находятся в `migration/evidence/2026-11-23/reading-split-check.json`.

Для локального предпросмотра из корня репозитория соберите сайт в новый каталог и запустите сервер.

```sh
preview_dir=$(mktemp -d)
python3 scripts/render_site.py --output "$preview_dir/site"
python3 -m http.server --bind 127.0.0.1 --directory "$preview_dir"
```

Предпросмотр доступен по адресу `http://localhost:8000/site/`.

## Индекс кода для AI-агентов

В проекте используется [codebase-memory-mcp](https://github.com/DeusData/codebase-memory-mcp) **0.12.1**: локальный граф файлов, функций и связей, доступный через MCP и командную строку. API-ключи не нужны. Установка поддерживает macOS (Apple Silicon и Intel) и Linux (ARM64 и x86_64); на Linux используется статическая portable-сборка. Нужны Python 3.9+, `curl` и доступ к GitHub. Скрипт работает самостоятельно: любой агент или человек может создать индекс без установленного AI-агента или MCP-клиента.

Из корня репозитория:

```sh
python3 scripts/code_index.py setup
```

Команда скачивает закреплённую сборку, проверяет SHA-256, сохраняет исполняемый файл и лицензии в `.tools/codebase-memory-mcp/` и индексирует этот репозиторий под именем `ufalit`. Конфигурации агентов она не читает и не изменяет. После клонирования на другой компьютер выполните ту же команду. Для отдельной установки без индексации используйте `python3 scripts/code_index.py install`.

Индекс хранится вне Git в стандартном кеше `~/.cache/codebase-memory-mcp/` (можно переопределить через `CBM_CACHE_DIR`). Исполняемые файлы также исключены из Git. Правила [.cbmignore](.cbmignore) убирают из индекса сторонние библиотеки, архив переноса, lock-файлы и большую XML-презентацию; исходники сайта, шаблоны, скрипты и код дизайн-примера остаются доступны.

HTML-страницы с JSON-метаданными в начале файла могут разбираться частично: индексатор сообщает об этом в `index_status`. Для точной проверки разметки читайте исходник напрямую; граф не заменяет сборку сайта и проверку HTML.

```sh
# Обновить индекс после изменения кода; это также можно сделать через MCP.
python3 scripts/code_index.py index

# Найти функцию и её связи.
python3 scripts/code_index.py cli search_graph --project ufalit --name-pattern render_page
python3 scripts/code_index.py cli trace_path --project ufalit --function-name render_page --direction both

# Проверить состояние индекса.
python3 scripts/code_index.py cli index_status --project ufalit
```

Подключение по MCP необязательно: все команды выше доступны из терминала любого агента. Чтобы использовать инструменты MCP, добавьте в настройки своего клиента stdio-сервер с командой `python3` и аргументами `["<абсолютный путь к репозиторию>/scripts/code_index.py", "serve"]`. Команда запускается из любого рабочего каталога. Альтернатива — абсолютный путь к `.tools/codebase-memory-mcp/codebase-memory-mcp` как команда сервера без аргументов. Если клиент не видит `python3` в `PATH`, укажите абсолютный путь к интерпретатору. Формат файла настроек зависит от MCP-клиента.

Проверка `setup` с системным `PATH` без CLI агентов, повторной установки, индексации и поиска функции выполняется в [GitHub Actions на macOS и Linux](.github/workflows/code-index.yml). При обновлении версии изменяйте `VERSION` и четыре SHA-256 в `scripts/code_index.py` по `checksums.txt` соответствующего официального релиза.
