# Уфа литературная — статическая копия

Сайт опубликован: **https://ufalit.ufacsdb.ru/**

Перенос с [исходного сайта](https://ufalit.ufacsdb.ru/) и редизайн выполнены и приняты пользователем 26 ноября 2026 года. История работ сохранена в [CHANGELOG.md](CHANGELOG.md) и Git. Временные материалы переноса удалены; открытых задач этих планов нет.

GitHub Actions собирает страницы из `site/` и общих шаблонов. Публикация собранного каталога `site/` запускается вручную в [workflow Pages](.github/workflows/pages.yml) с параметром `deploy`. Прежняя ветка `gh-pages` сохранена как история первой публикации.

Общий каркас, шапка, меню, хлебные крошки и футер редактируются в [templates/](templates/). В начале каждого исходного HTML между строками `---` записаны параметры страницы в JSON. Поле `title` задаёт заголовок вкладки, `breadcrumbs` — последовательность подписей и ссылок, `styles` и `scripts` — дополнительные файлы из `site/assets/` (скрипты и стили справочника, читального зала, просмотра иллюстраций, аудиостудии и библиографии подключаются автоматически по разметке и параметрам). После параметров идёт HTML основного материала. На главной метка `<!-- main -->` отделяет вступление перед основным содержанием, массив `guide_cards` заполняет карточки разделов внутри статьи. Отдельная страница `site/pages/map/index.html` включает карту параметром `atlas` на месте `<!-- atlas -->`; ссылка на неё находится в общем меню.

Карта использует общий виджет `site/assets/map-widget.js`, адаптированный из пользовательского макета; его происхождение указано в [THIRD_PARTY.md](THIRD_PARTY.md). Единственный источник её мест, координат, фотографий и описаний — [atlas-places.json](templates/atlas-places.json); сборщик формирует из него список ссылок, начальную карточку и JSON для браузера. Оформление карты — `site/assets/atlas.css`, логика раздела карты — `site/assets/ufalit-map.js`, общий виджет — `site/assets/map-widget.js`. Поиск и фильтры работают и при недоступной подложке. Библиотека MapLibre GL JS 6.19.0, её CSS, worker и лицензия находятся в `site/assets/vendor/maplibre-gl/`; картографическая подложка и шрифты подписей загружаются с OpenFreeMap. Атрибуция поставщиков сохранена на карте. Проверка: `node scripts/test_home_map.js`.

Порядок добавления и исправления меток, описание полей, категории фильтров и проверки собраны в [инструкции по меткам карты](AGENTS.md#метки-литературной-карты).

Координаты демонстрационного сада исправлены по [географической привязке сада Аксакова](https://ru.wikipedia.org/wiki/Сад_Аксакова); для музея Гафури использован [адресный справочник](https://ufa.spravka-region.ru/tags/muzei/Memorialnyj-dom-muzej-M-Gafuri-3), для библиотеки — [привязка здания на ул. Мингажева, 109](https://bashkortostan.spravochnika.ru/c-ufa/biblioteki). Точка улицы Мустая Карима обозначает её центральный участок, а не отдельное учреждение. Тексты и архивные фотографии сохранены из прежней карты и раздела памятных мест.

Фотогалерея использует общие [шаблон альбома](templates/gallery-album.html), [карточку литератора](templates/gallery-writer.html) и [карточку фотографии](templates/photo.html). Порядок литераторов и краткие описания подборок хранятся в [gallery-catalog.json](templates/gallery-catalog.json); имена, годы жизни, портреты и адреса альбомов берутся из `writers.json`. Снимки остаются в исходных массивах `photos`, обязательное поле `heading` задаёт название альбома, в том числе для подборок без собственных снимков. Страница литератора собирает его вложенные подборки по существующим ссылкам, сохраняя порядок и исключая повторный обход обратных ссылок. Вложенные альбомы и прежние якоря `#photo-*` продолжают работать.

Обычная подпись хранится в `caption`, подпись с разметкой — в `caption_html`; для отдельного описания изображения используется `alt`. Дополнительные поля: `note` — пояснение, `address` — подтверждённое местоположение, `year` — дата или эпоха, `category` — категория фильтра. Поле `hide_caption: true` скрывает служебную подпись и метаданные кадра; исходный текст сохраняется в записи фотографии. Категория по умолчанию — «Фотоархив». Категорию, место и дату задавайте явно в записи фотографии; сборщик выводит эти поля без анализа подписи. Снимки загружаются с `loading="lazy"`; для исключений укажите `"loading": "eager"` либо `"loading": null` (пропустить атрибут). Стили `gallery.css` и скрипт `ufalit-gallery.js` задают музейное паспарту, архивный стол с диафильмом, журнальную кладку и контактный лист. Все карточки литераторов показаны сеткой в три столбца (два или один на узких экранах); нажатие выбирает подборку и прокручивает страницу к фотографиям. Поиск ищет по подписям всех литераторов, независимо от выбранной карточки. Остальные снимки включены в неактивный `<template>` и добавляются в галерею только при поиске или смене автора; дополнительные запросы к серверу не нужны. Поиск и фильтр ограничивают также набор кадров в полноэкранном просмотре с лупой 2,8×, увеличением и кнопками трёх тем. Шапка просмотра показывает подпись, литератора и положение в подборке; внутренние идентификаторы снимков сохраняются только в якорях. Выбранный вид запоминается на время сеанса. Без JavaScript доступны карточки, подписи и ссылки на оригиналы. Проверка всех альбомов, подписей, вложенных подборок и локальных ссылок: `python3 scripts/test_gallery.py`.

В статьях иллюстрации внутри `.material-figure`, `.material-inline` и `.legend-figure` записываются как обычные `<img>` и при сборке автоматически оборачиваются ссылкой на оригинал по [шаблону иллюстрации](templates/zoom-image.html).

В каталогах у ссылки на альбом укажите `data-cover` с путём к обложке либо `data-writer` с ключом писателя из [writers.json](templates/writers.json) — сборка подставит портрет, имя и адрес раздела. В справочниках (`personalities`, `places`, `awards`) шапка формируется по `heading` и `intro` через [шаблон баннера](templates/directory-banner.html). На страницах с аудио объект `audio_studio` формирует [аудиостудию](templates/audio-studio.html), а массив `tracks` (`id`, `title`, `src`) на месте `<!-- tracks -->` выводит дорожки по [шаблону аудиозаписи](templates/audio-track.html). На видеостраницах поле `heading` и массив `videos` (`title`, `src`, при необходимости `id` и `description`) формируют страницу по [шаблону видеоподборки](templates/video-album.html) и выводят карточки по [шаблону видеозаписи](templates/video.html). GitHub Actions собирает готовые HTML перед публикацией.

«Видеокопилка» оформляется отдельными шаблонами `templates/archive-*.html`, стилями `site/assets/video-archive.css` и скриптом `site/assets/ufalit-video.js`. Поле `video_archive` на странице коллекции ссылается на писателя из `writers.json`; список `video_collections` на странице каталога задаёт порядок коллекций. Имена, портреты и количество записей подставляются из этих источников при сборке. Названия и MP4-ссылки остаются в исходных массивах `videos`. На странице коллекции один нативный плеер: выбор превью запускает запись и обновляет заголовок, заставку и ссылку скачивания. Без JavaScript плеер показывает первую запись, остальные ссылки открывают исходные MP4. Превью в `site/assets/video-archive/previews/<коллекция>/<имя MP4>.jpg` содержат настоящие кадры соответствующих роликов, размер — не более 640×360 пикселей; это небольшие обычные Git-файлы, исключённые из LFS. При добавлении записи добавьте её превью с тем же именем файла. Банки на витрине содержат портрет, имя писателя и количество записей на одной этикетке.

Проверка видеокопилки: `python3 scripts/test_video_archive.py` (один плеер, пустые коллекции, добавление новых записей, превью, ссылки скачивания и отсутствие ссылок на отсутствующие медиафайлы).

Читальный зал содержит Сергея Аксакова (три материала о книгах) и Тухвата Янаби (четыре произведения). Он состоит из каталога литераторов, страниц `reading-author-<ключ>` со списком материалов и страниц отдельных произведений. В `templates/reading-room.json` массив `works` задаёт единственный список материалов, а `groups` — их подборки и общие пояснения `notes_html`, которые выводятся под заголовком «Произведения и материалы». Поле `group` связывает произведение с подборкой; `author` при необходимости уточняет автора отзыва или посвящения. Портреты и сведения об авторах берутся из `templates/writers.json`. Общие шаблоны `reading-*.html`, стили `reading-room.css` и `ufalit-library.js` отвечают за витрину и полки. Биографии, библиографии и посвящения в других разделах сохранены. Ссылки из профилей в читальный зал появляются только для авторов с полем `reading`.

Все необходимые видеозаписи находятся на месте; текущий состав принят владельцем. Аудио полностью удалено по его решению, дополнительных работ с ним не требуется. Пустые видеоколлекции сохраняют плеер и оформление без `src`, заставок и активных ссылок скачивания. Существующие шаблоны медиа сохранены. Для добавления новой записи разместите файл в `site/assets/` и укажите существующий путь в метаданных страницы. Проверка видеокаталога контролирует ссылки на опубликованные записи.

При сборке в каталог читального зала встраивается полнотекстовый индекс его отдельных материалов. Общесайтовый поиск исключён из объёма работ по решению пользователя. `ufalit-search.js` ищет целые слова, поддерживает точные фразы в кавычках и равнозначные «е/ё», ранжирует совпадения и формирует фрагменты с подсветкой. Короткие служебные слова не подсвечиваются внутри многословного запроса; цельная найденная фраза подсвечивается целиком. Запрос сохраняется в параметре `q`; ссылки из результатов используют текстовые фрагменты браузера для перехода к совпадению. Индекс обновляется автоматически при изменении материалов. Проверка поиска на настоящем корпусе: `node scripts/test_reading_search.js`.

`ufalit-reader.js` добавляет темы, размер текста, режим «Только текст», прогресс и сохранение позиции в этом браузере. Старые ссылки `reading/#read-<ключ>` открывают полку автора. Проверка охвата каталога, переходов, авторства, сохранности исходных абзацев и иллюстраций: `python3 scripts/test_reading_room.py`. Контрольные данные для сохранённых текстов и посвящений находятся в `scripts/fixtures/reading-split-check.json`.

Для локального предпросмотра из корня репозитория соберите сайт в новый каталог и запустите сервер.

```sh
preview_dir=$(mktemp -d)
python3 scripts/render_site.py --output "$preview_dir/ufalit"
python3 -m http.server --bind 127.0.0.1 --directory "$preview_dir"
```

Предпросмотр доступен по адресу `http://localhost:8000/ufalit/` — с тем же префиксом, что и GitHub Pages. `--in-place` используйте только в одноразовом CI checkout: команда перезаписывает исходники собранным HTML.

Для воспроизведения видео в локальном предпросмотре нужны сами файлы Git LFS. Если checkout содержит указатели вместо MP4, загрузите записи командой `git lfs pull --include='site/assets/video/**'`. В CI это делает `actions/checkout` с `lfs: true`.

Почтовые ссылки в исходниках можно записывать обычным `<a href="mailto:…">`. Общий сборщик защищает ссылки из материалов и общих шаблонов: в опубликованном HTML остаётся кнопка «Написать письмо» (либо исходная подпись без адреса) и закодированный адрес; почтовая программа открывается по нажатию. Параметры письма сохраняются. Адреса также исключаются из текста поискового индекса. Без JavaScript выводится пояснение. Защита затрудняет простой сбор адресов из HTML; боты, исполняющие JavaScript, и читатели открытого репозитория могут восстановить адрес. Сейчас почтовых ссылок в материалах нет.

## SEO и аналитика

Основной адрес для canonical, sitemap и социальных карточек — `https://ufalit.ufacsdb.ru/`, константа `SITE_URL` в `scripts/seo.py`. Относительные ссылки также работают под `/ufalit/`. Метаданные страниц поддерживают `description`, `canonical` (абсолютный либо относительно страницы), `og_image` (от корня сайта или абсолютный), `og_type`, `robots` и `schema_type`. Не задавайте noindex или чужой canonical без документированной причины в `templates/seo-exclusions.json`. Даты lastmod не подставляются автоматически.

Сборщик создаёт `sitemap.xml` из реальных конечных страниц. `site/robots.txt` предназначен для корня пользовательского домена. `templates/metrika.html` и `site/assets/ufalit-analytics.js` подключают счётчик 110934501 и события; цели надо добавить в аккаунте Метрики по [инструкции владельцу](SEO_OWNER_GUIDE.md).

Большие изображения используют сохранённые WebP-превью из `site/assets/optimized/`; оригинальные src и ссылки не меняются. Для нового или заменённого снимка сначала соберите предпросмотр, затем с установленным Pillow выполните `python3 scripts/optimize_images.py --site /tmp/ufalit-seo-preview` и пересоберите в новый каталог. Скрипт не изменяет оригиналы; обычная сборка не требует Pillow. Устаревшие превью заменённого снимка нужно пересоздать до публикации.

После добавления или замены фотографии в `templates/atlas-places.json` запустите `python3 scripts/optimize_images.py --atlas` с установленным Pillow. Сохраните в Git сгенерированные файлы из `site/assets/atlas/`: метки и список используют WebP 128 × 128, карточки мест и прогулки — WebP до 640 пикселей по длинной стороне.

Аудит: `python3 scripts/audit_seo.py --site /tmp/ufalit-seo-preview --output /tmp/ufalit-seo-audit.json --details`. Опция `--live` проверяет публичные страницы по сети. Документы: [исходный аудит](SEO_AUDIT.md), [семантика](SEO_KEYWORDS.md), [проверки](SEO_VALIDATION.md), [продвижение](SEO_PROMOTION.md).

GitHub Actions запускает эти же проверки. Push в `main` собирает артефакт; публикация выполняется только ручным запуском workflow Pages с `deploy: true`. Успешный push сам по себе не обновляет публичный сайт.

## Индекс кода для AI-агентов

В проекте используется [codebase-memory-mcp](https://github.com/DeusData/codebase-memory-mcp) **0.12.1**: локальный граф файлов, функций и связей, доступный через MCP и командную строку. API-ключи не нужны. Установка поддерживает macOS (Apple Silicon и Intel) и Linux (ARM64 и x86_64); на Linux используется статическая portable-сборка. Нужны Python 3.9+, `curl` и доступ к GitHub. Скрипт работает самостоятельно: любой агент или человек может создать индекс без установленного AI-агента или MCP-клиента.

Из корня репозитория:

```sh
python3 scripts/code_index.py setup
```

Команда скачивает закреплённую сборку, проверяет SHA-256, сохраняет исполняемый файл и лицензии в `.tools/codebase-memory-mcp/` и индексирует этот репозиторий под именем `ufalit`. Конфигурации агентов она не читает и не изменяет. После клонирования на другой компьютер выполните ту же команду. Для отдельной установки без индексации используйте `python3 scripts/code_index.py install`.

Индекс хранится вне Git в стандартном кеше `~/.cache/codebase-memory-mcp/` (можно переопределить через `CBM_CACHE_DIR`). Исполняемые файлы также исключены из Git. Правила [.cbmignore](.cbmignore) убирают из индекса сторонние библиотеки, архив переноса, lock-файлы и большую XML-презентацию; исходники сайта, шаблоны, скрипты и код дизайн-примера остаются доступны.

HTML-страницы с JSON-метаданными в начале файла могут разбираться частично: индексатор сообщает об этом в `index_status`. Для точной проверки разметки читайте исходник напрямую; граф не заменяет сборку сайта и проверку HTML.

```sh
# Обновить индекс после изменения кода; это также можно сделать через MCP.
python3 scripts/code_index.py index

# Найти функцию и её связи.
python3 scripts/code_index.py cli search_graph --project ufalit --name-pattern render_page
python3 scripts/code_index.py cli trace_path --project ufalit --function-name render_page --direction both

# Проверить состояние индекса.
python3 scripts/code_index.py cli index_status --project ufalit
```

Подключение по MCP необязательно: все команды выше доступны из терминала любого агента. Чтобы использовать инструменты MCP, добавьте в настройки своего клиента stdio-сервер с командой `python3` и аргументами `["<абсолютный путь к репозиторию>/scripts/code_index.py", "serve"]`. Команда запускается из любого рабочего каталога. Альтернатива — абсолютный путь к `.tools/codebase-memory-mcp/codebase-memory-mcp` как команда сервера без аргументов. Если клиент не видит `python3` в `PATH`, укажите абсолютный путь к интерпретатору. Формат файла настроек зависит от MCP-клиента.

Проверка `setup` с системным `PATH` без CLI агентов, повторной установки, индексации и поиска функции выполняется в [GitHub Actions на macOS и Linux](.github/workflows/code-index.yml). При обновлении версии изменяйте `VERSION` и четыре SHA-256 в `scripts/code_index.py` по `checksums.txt` соответствующего официального релиза.
