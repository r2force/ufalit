# Независимая проверка очереди detail-queue

Дата: 2026-11-14

## Объём и метод

Проверены все 147 строк `detail-queue-candidate.tsv`. Для каждой строки заново разобраны catid/item ID в исходном URL; прочитан указанный detail snapshot (сверены существование, SHA-256, и наличие в HTML ссылки с теми же catid/item ID); разрешены целевой путь/figure ID и проверено, что ровно одна целевая figure содержит изображение, чей относительный путь указывает на назначенный файл. Файл проверен на наличие, ненулевой размер, локальный SHA/размер против строки `assets.csv` и тип файла против MIME. `assets.csv` проверен на точное совпадение URL/target path/status/MIME/bytes/SHA/evidence path. Протокол загрузки оценивался отдельно от самого наличия записи реестра.

Этот аудит проверяет учет и локальную связность, а не пиксельную/сюжетную идентичность изображения, полноту исходного обхода, подписи или статус `verified/matched`. Внешний источник не запрашивался.

## Итог

- Проверено 147 строк в категориях: 1: 27, 2: 19, 3: 15, 5: 1, 8: 30, 10: 9, 11: 20, 12: 18, 18: 8.
- Для всех 147 URL численные `catid`/`id` совпадают с полями строки; все 147 snapshots существуют, их сохранённые SHA-256 совпали, и каждый содержит ссылку с той же парой category/item ID.
- Все 147 локальных target assets существуют, ненулевые; точная строка `assets.csv` имеет статус `captured`, HTTP 200; записанные bytes/SHA совпадают с локальным файлом и с candidate. Все signature/MIME пары совпали; распределение MIME: image/gif 1, image/jpeg 139, image/png 7.
- Все 147 целевых HTML существуют; каждый указанный `#photo-ID` встречается ровно в одной figure, и её img src разрешается в назначенный локальный asset.
- Для 78 строк есть конкретный headers-файл с HTTP 200, MIME и Content-Length, согласованными с записью/файлом; для 23 есть строка прямого TSV-журнала с согласованными transfer metadata. Прямых transfer records всего 101.
- Для 46 строк поле evidence указывает на HTML detail snapshot, а не на ответ/журнал загрузки файла. Сам снимок идентифицирует нужный исходный detail, но не подтверждает передачу файла. У этих строк есть локальный файл и совпадающая строка `assets.csv` с recorded HTTP 200/размером/SHA; прямой transfer artifact отсутствует.
- По формальной записи реестра все строки `captured`; это не повышает их до `verified` или `matched`. Для 46 строк качество evidence для факта загрузки слабее и отдельно помечено в TSV.

## Распределение подтверждений загрузки

| Вид evidence | Число | Оценка |
|---|---:|---|
| Headers-файл | 78 | HTTP статус, MIME и размер сверены с регистрацией/файлом; SHA проверен по `assets.csv` и локальному файлу. |

Идентификаторы 46 строк с непрямым download evidence указаны в `detail-queue-review.tsv` с `review_result=captured_indirect_download_evidence` и issue `no_direct_download_response_record`.

## Вывод

На уровне дерева сайта все 147 строк имеют соответствующий локальный файл и целевое размещение; на уровне реестра все 147 зарегистрированы как `captured`, и metadata согласуется с target bytes. Однако только 101 строка имеет прямое transfer evidence. Для остальных 46 кандидат недооценивает разницу между source snapshot и журналом/ответом загрузки. Сохранять их как `captured` можно лишь с оговоркой, что связанный evidence-файл не подтверждает HTTP-передачу; чтобы закрыть именно доказательство захвата, нужно заменить/дополнить evidence прямым журналом/ответом. Ни одна из этих проверок не доказывает содержательное `verified/matched` соответствие изображений.

## Машиночитаемые результаты

`detail-queue-review.tsv` содержит 147 строк с независимыми результатами, локальными bytes/SHA, asset registration, типом transfer evidence, figure locator/path и точными issue flags.
