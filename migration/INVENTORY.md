# Реестры переноса

Формат: CSV UTF-8 с заголовком; значения с запятыми, кавычками и переносами экранировать по правилам CSV. Пустая ячейка означает «ещё не установлено», а не ноль. Пути — относительно корня репозитория, с учётом регистра. Даты проверок — ISO 8601 с часовым поясом.

## pages.csv — очередь и карта URL

`source_url,discovered_from,section,kind,canonical_url,target_path,status,checked_at,evidence,notes`

- `source_url`: каждый обнаруженный исходный адрес. Порядок query-параметров можно нормализовать; параметры содержимого не удалять без проверки. Фрагмент не входит в ключ загрузки, но сохраняется в ссылках.
- `discovered_from`: где нашли URL; для стартового списка — `seed`.
- `kind`: `article`, `category`, `gallery-category`, `gallery-detail`, `other`.
- `canonical_url`: заполнить после доказанного объединения дублей. Не объединять разные Joomla-компоненты только по `id` и не считать `Itemid` заведомо лишним.
- `target_path`: фактический статический файл в `site/`; также задаёт карту старого адреса в новый. Все вариации проверенного дубля указывают на один файл.
- `status`: `discovered → captured → verified`; отдельные исходы `blocked`, `excluded`. `captured` требует файла; `verified` — выполненных проверок. Для `excluded`/`blocked` обязательна запись в исключениях.
- `checked_at`, `evidence`: время и ссылка на подтверждение последней проверки. Для стартовых URL пусты: обзор через веб-инструмент не является проверкой копии.

Новые найденные ссылки добавлять в очередь, пока обход согласованного охвата не перестанет давать новые URL. Пагинацию учитывать полностью. `pages.csv` сейчас содержит только девять стартовых адресов.

## assets.csv — файлы и зависимости

`source_url,used_by,target_path,kind,status,http_status,mime,bytes,sha256,checked_at,evidence,notes`

`kind`: `image`, `thumbnail`, `document`, `video`, `audio`, `css`, `font`, `script`, `other`. Для нескольких потребителей разрешены несколько строк с одним файлом; при подсчёте уникальных ресурсов учитывать `source_url`, при подсчёте сохранённых файлов — `target_path`/хеш.

Статусы: `discovered`, `captured`, `verified`, `external`, `blocked`, `excluded`. Для `external` оставить исходную ссылку, описать зависимость и обоснование; этот статус не означает локальное сохранение. `http_status`, MIME и число байтов — фактические, не предполагаемые по расширению. SHA-256 считать по сохранённым байтам. При дедупликации оставлять происхождение каждого URL. Старые декоративные CSS/JS, заменённые редизайном, обозначать excluded с причиной design-replaced в notes; это не исключение исторического содержания. Новые CSS/шрифты и производные изображения учитывать с происхождением и лицензией; для изменённых файлов хранить исходный и конечный хеши в evidence.

## exceptions.csv — пропуски и ограничения

`id,source_url,category,impact,status,decision,evidence,updated_at`

`category`: `access`, `missing-source`, `dynamic-feature`, `external-dependency`, `size-limit`, `legacy-url`, `other`. `status`: `open`, `resolved`, `accepted`. `accepted` допустим только после решения пользователя с ссылкой/датой в evidence; агент не принимает собственные существенные пропуски от имени пользователя.

`impact` описывает конкретно, что недоступно посетителю. `decision` — дальнейшее действие или принятое ограничение. Повторные попытки отмечать в evidence без создания дубликатов одной проблемы. Технические ограничения среды вести в `STATUS.md`; в exceptions добавлять их, когда они блокируют конкретные материалы.

## content-parity.csv — содержание старого и нового сайта

Схема и обязательный протокол — в [CONTENT_PARITY.md](CONTENT_PARITY.md). Реестр связывает каждый текстовый блок, значимое вхождение картинки, видео и документ со старого сайта с конкретной целью на новом. Он дополняет реестры файлов и URL: один файл может иметь несколько значимых размещений. Сейчас только заголовок, без вымышленных проверок.

## Итоговый QA.md

Создать после пилота, затем обновлять по партиям. Указать дату, SHA проверенной версии, инструмент и точную команду/действие, охват и результат каждой проверки, ссылки на доказательства, незавершённые проверки и исключения. Не добавлять успешных отметок заранее.

Отдельно показать сводку content-parity.csv по text/image/video/document: всего исходных элементов, matched, missing, changed, blocked, discovered, accepted-exception и долю matched. Исключения не включать в процент совпадений. Привести полный список расхождений с доказательствами и локаторами старого и нового сайта.

Числа выводить из реестров: уникальные URL, уникальные страницы после дедупликации, сохранённые файлы, проверенные файлы, внешние зависимости, блокировки, исключения и размер готового сайта. Проверить, что каждая строка с `captured`/`verified` соответствует существующему файлу, а каждый публикуемый файл учтён как страница, ресурс или служебный файл (`404.html`, `.nojekyll`).
