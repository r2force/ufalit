# «Уфа литературная»: дизайн-план и прототип

## Задача и оценка существующей версии

Сайт — не промостраница, а детский и семейный литературно-краеведческий путеводитель. Важнейшие сценарии: найти автора и связанное с ним место, прочесть произведение, рассмотреть архивные фотографии, перейти к аудио- и видеоматериалам. Сохраняем адреса, полные тексты, авторство, порядок и подписи; оформление не является поводом переписывать источники.

В текущем проекте уже есть сильная техническая база: статический HTML, локальные шрифты, адаптивность, алфавитные фильтры, настройки чтения, доступ к оригиналам и диалог просмотра. Основные проблемы: главная содержит много одинаково значимых блоков и мало связи с реальным городом; часть интерфейса чрезмерно упакована в рамки; каталог и отдельные страницы видео отличаются от остального сайта; архивным изображениям нужна более ясная и спокойная подача. На видеостраницах ссылки ведут на внешние FLV, а не на проверенные браузерные видео — обещать воспроизведение нельзя. Это оценка репозитория и сгенерированного HTML, а не результат полноценного аудита доступности или сравнения всех браузеров.

## Концепция: городской литературный архив

Первым показываем реальное место из коллекции — Аксаковский сад, а не абстрактную иллюстрацию. Крупная книжная типографика, прохладные оттенки воды и зелени, чистая поверхность и выдержанные подписи объединяют городскую карту, архив и читальный зал. Эпиграф остаётся частью истории, но не конкурирует с названием. Убираем лишнюю декоративность и одинаковые тяжёлые карточки. Фото-оригиналы и подписи остаются главными экспонатами.

### Токены и принципы

| Роль | Значение | Применение |
| --- | --- | --- |
| Текст | `#203d42` | основной текст и заголовки |
| Фон | `#f2f6f4` | спокойное поле страниц |
| Поверхность | `#ffffff` | статьи и фотографии |
| Вторичный фон | `#e6efec` | паспарту, технические панели |
| Акцент | `#27696d` | действия, интерактивные состояния |
| Контур | `#d1dfda` | границы и делители |

Локальные Cormorant Garamond — выразительные заголовки, Literata — литературное чтение, Inter — навигация и подписи. Контейнер до 78 rem, внутренние поля через `clamp()`, длина строк статей около 60–75 символов. Сетка на Grid, без горизонтального скролла страницы; на узком экране все основные блоки идут одним столбцом. Фокус видим, ссылки не зависят от цвета или hover. Интерактив по запросу пользователя, без автопрокрутки. Уважать `prefers-reduced-motion`.

Пример токенов и адаптивного блока:

```css
.museum { --ink: #203d42; --paper: #f2f6f4; --accent: #27696d; }
.feature { display: grid; grid-template-columns: repeat(2, minmax(0, 1fr)); gap: clamp(1.5rem, 4vw, 4rem); }
@media (max-width: 44rem) { .feature { grid-template-columns: minmax(0, 1fr); } }
@media (prefers-reduced-motion: reduce) { html { scroll-behavior: auto; } }
```

## Архитектура страниц

1. **Главная.** Название и назначение, понятные входы в персоналии и аудио, подлинная фотография с подписью и переходом к оригинальному альбому, эпиграф, маршруты по разделам и схема литературных мест. Полный текст «О проекте» остаётся на странице. При следующей итерации проверить порядок разделов по реальным сценариям пользователей.
2. **Персоналии и места.** Сохранить алфавит, поиск, раскрытие полных текстов и привязанные ссылки. Избегать дублирующихся фильтров и липких блоков, занимающих большую часть мобильного экрана. При добавлении новых связей подтверждать их источниками.
3. **Читальный зал.** Разделять навигацию и непосредственно чтение; оставлять стихи с исходными переносами строк, библиографию и изображения. Настройки размера и цвета текста — дополнение, а не условие доступа.
4. **Фотогалерея.** В каталоге использовать узнаваемые портреты и названия альбомов. В альбоме: равномерная сетка, фото целиком в паспарту, читаемые подписи; альтернативные виды — диафильм, журнальная кладка и контактный лист. Без JS все изображения остаются ссылками на оригинал. В увеличенном просмотре — номер, подпись, предыдущая/следующая, увеличение, оригинал, закрытие, Esc и возврат фокуса. Не обрезать оригиналы, не сортировать кадры автоматически. Для больших альбомов отдельно подготовить оптимизированные миниатюры с сохранением исходных файлов и метаданных, явно проверив порядок.
5. **Видео.** Сейчас честная карточка-ссылка FLV с названием и предупреждением; без выдуманных постеров и кнопок «смотреть». Когда будут подтверждены и публично доступны совместимые MP4, добавить штатный `<video controls preload="metadata">`, заголовок, текстовое описание, субтитры при наличии, ссылки на оригинал и скачивание. Не автозапускать, не заменять исходные FLV и не обещать работоспособность непроверенных файлов. Файлы в `site/assets/video/` представлены LFS-указателями; прежде чем их подключать, проверить фактическую выдачу и права/размеры размещения.
6. **Легенды и документы.** Оставить подписи к изображениям и возможность скачать исходную презентацию; общий просмотрщик — прогрессивное улучшение. Сохранять возможность отдельного открытия каждого изображения.

## Интерактив и примеры для агента

Текущий `ufalit-gallery.js` уже использует нативный `dialog`, четыре режима сетки, клавиши, увеличение и восстановление фокуса. При дальнейшем развитии можно добавить касательное перелистывание только в незумированном состоянии и кнопку полноэкранного режима; видимые кнопки при этом обязательны. Нельзя перехватывать свайп в увеличенном изображении, где пользователь перемещается по самому кадру. Пример надёжного возврата фокуса:

```js
let opener;
function openViewer(link) {
  opener = link;
  dialog.showModal();
}
dialog.addEventListener('close', () => opener?.focus());
// Esc обеспечивается браузером; ссылки на оригиналы работают и без JS.
```

Пример будущего видео только после проверки реального MP4 и подписей:

```html
<figure>
  <video controls preload="metadata" playsinline>
    <source src="проверенный-локальный-файл.mp4" type="video/mp4">
  </video>
  <figcaption>Подлинная подпись записи</figcaption>
  <a href="исходная-ссылка.flv">Исходный файл FLV</a>
</figure>
```

Это схема, не готовый путь к файлу. Не подключать до проверки выдачи настоящих байтов вместо Git LFS pointer. Без JavaScript нативные контроли и ссылки должны работать. Если будет нужен список записей рядом с плеером, использовать обычные ссылки как базу и подключать выбор записи прогрессивно, не пряча оригиналы.

## Что реализовано в этой ветке

- Новая композиция главной с реальным фото сада из существующего альбома, подписью и ссылкой на конкретный кадр; эпиграф и содержание сохранены.
- Единая прохладная цветовая система и типографическая иерархия, более спокойные карточки, галереи и элементы управления.
- Видеокаталог и четыре страницы видеоматериалов получили общую навигацию и оформление; исходные адреса и предупреждения оставлены. Воспроизведение FLV не добавлено.
- Просмотрщик закрывается также нажатием на подложку, сохраняя существующие управление и fallback.
- Существующие фильтры, схема мест, режимы галереи и аудиоплееры сохранены, а не переписаны.

## Проверка и следующие шаги

Сборка: `python3 scripts/render_site.py --output /tmp/ufalit-preview/site`. Затем `python3 -m http.server --bind 0.0.0.0 --directory /tmp/ufalit-preview/site`. Исходники `site/*.html` с метаданными — не готовые HTML, проверять именно собранную копию; Pages собирает её при публикации из main.

Приёмка перед внедрением: сравнить тексты, порядок фотографий, подписи, ID и видео-URL с базой; обойти внутренние ссылки; открыть главную, каталог, длинный альбом, авторские страницы, чтение, легенды и видео. Проверить 320/360 px, планшет, desktop, 200% масштаб, клавиатуру, Esc, фокус, работу без JS, reduced motion, оригиналы и длину подписей. Проверить Chrome, Firefox и Safari по возможности, контраст и работу вспомогательных технологий; не заявлять WCAG-соответствие без аудита. Для MP4 — фактическая загрузка, звук, перемотка, субтитры и лицензии по каждой записи. Подготовить оптимизированные копии только после сверки и измерения скорости; архивные оригиналы не изменять. Не объединять ветку с main и не менять публикацию без отдельного решения пользователя.
