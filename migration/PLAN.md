# План переноса

Дата подготовки: 11 ноября 2026 года. Репозиторий: `r2force/ufalit`.

## Подход

Переносить публично доступное содержание Joomla: полные тексты, изображения, документы и видео. Оформление создать заново по `DESIGN.md`, сохранив характер исходного проекта. Использовать готовые средства скачивания и проверки, а не экспорт базы и собственный конвертер. Получится обычный набор файлов, которому не нужны Joomla, PHP или база данных. Современную статическую HTML/CSS-вёрстку, доступные галереи и адаптацию ссылок выполняет агент. Пользователь не пишет код.

Старый макет и оформление не копировать. Сохранить идентичность проекта, содержание, тематические связи и узнаваемые мотивы, подтверждённые будущим визуальным обследованием. Применить новый адаптивный дизайн и современные нативные HTML/CSS-возможности. Серверные функции не объявлять работающими после копирования: для каждой найти статический эквивалент или зафиксировать исключение.

## Охват

Начальные разделы: о проекте, персоналии, памятные места, читальный зал, фотогалерея, видеокопилка, конкурсы/награды/фонды/праздники, легенды и предания. Это точки входа, не окончательное количество страниц.

Скачивать размещённые на исходном домене изображения в статьях и галереях, оригиналы и превью, PDF и другие вложения, осмысленные иллюстрации и элементы идентичности проекта. Старые CSS/JS изучать как справку и для выявления зависимостей; устаревший шаблон не переносить. Чисто декоративные ресурсы старого оформления учитывать отдельно как заменённые дизайном, не смешивать с пропавшим содержанием. Карту и её реальные зависимости ещё предстоит найти: описание проекта не доказывает наличие работоспособной интерактивной карты.

Внешние сайты не зеркалировать рекурсивно. Внешние видео и карты учитывать отдельно: сохранить подпись, URL и пригодное штатное встраивание. Для видео подтвердить тот же материал и реальное воспроизведение; ссылка или постер не доказывает полноценный перенос. При невозможности воспроизведения записать блокировку и предложить ссылку как явное исключение, не ставя совпадение автоматически. Файлы с других принадлежащих проекту доменов сначала выделить в реестре и определить охват; не считать внешнее размещение причиной молча пропустить нужное вложение.

## Адреса Joomla

Параметры `option`, `view`, `id`, `Itemid`, `limitstart` и прочие могут менять содержимое. Для каждого уникального содержания назначить путь вида `site/pages/<component>-<view>-<id>/index.html`, при коллизии добавить детерминированный суффикс и записать правило. Для главной — `site/index.html`. Не использовать `?` и `&` в именах файлов.

В `pages.csv` хранить каждую найденную URL-вариацию и её конечный статический путь. Одинаковое содержимое нескольких адресов может указывать на один файл после проверки. Якоря сохранять и проверять отдельно от идентичности страницы.

Все внутренние ссылки переписать на новые файлы. GitHub Pages не исполняет Joomla; таблица соответствий сама по себе не делает старые `index.php?...` рабочими редиректами. Сохранение таких внешних входящих ссылок на старом домене потребует отдельно согласованного решения на прежнем хостинге. Не обещать его в рамках статической копии.

## Технические решения без разработки приложения

- Основной инструмент выбрать после проверки среды: готовый зеркалировщик, например GNU Wget/HTTrack, плюс браузер для проверки галерей и динамических ссылок. Доступность ни одного из них сейчас не подтверждена.
- Если готовый инструмент даёт файлы с Joomla query в имени, использовать их только как временную загрузку; агент назначает чистые пути по реестру и исправляет ссылки.
- Не заменять скачивание полных исходников текстом поисковой выдачи или извлечённым кратким представлением страницы.
- Выбрать относительные пути, работающие при размещении в `/ufalit/`, и проверить вложенные страницы. Не использовать `<base>` со старым доменом.
- Сначала проверить неизвестные объёмы медиа. Лимиты GitHub/Pages сверять перед загрузкой и публикацией; не решать проблему больших файлов молчаливым удалением или Git LFS без проверки поддержки Pages.
- Без логина, отправки форм и серверных операций. Функции поиска, входа, комментариев, печати, галереи, карт и видео учесть в матрице возможностей; оставлять видимые неработающие элементы нельзя.

## Приёмка

Обязательны [CONTENT_PARITY.md](CONTENT_PARITY.md) и поэлементная матрица `content-parity.csv`: каждый текстовый блок, каждое значимое вхождение картинки и каждый видеоматериал сопоставить с конкретным местом готового сайта. Сверять весь охват, не выборку. Отдельно считать совпадения текста, изображений и видео; равные количества без проверки идентичности недостаточны. Перед финальной приёмкой обработать изменения источника после исходного снимка.

Для каждой страницы сравнить извлечённый основной текст сохранённого источника и результата после нормализации только пробелов/переносов. Не исключать библиографию, подписи или длинные списки. Для каждого вложения проверить ответ, фактический MIME, размер и SHA-256; HTML ошибки под видом JPEG/PDF не принимать.

Автоматически или готовыми валидаторами проверить все локальные ссылки, `src`, `srcset`, CSS `url()`/`@import`, фрагменты и регистр имён. Браузером проверить новый дизайн всех типов страниц на широком и узком экране, увеличение текста, клавиатуру и reduced motion; полное содержание длинных статей, все галереи, документы и каждый видеоматериал. Сравнивать сохранность контента, не пиксельное совпадение макетов. Основные тексты и локальные медиа должны работать с заблокированным `ufalit.ufacsdb.ru`; внешние зависимости перечисляются отдельно.

Отчёт содержит обнаружено/сохранено/проверено/исключено/заблокировано для страниц и ресурсов; перечень внешних зависимостей; общий размер; результаты проверок, ограничения и SHA версии. Отсутствие доступа к инструменту — статус «не проверено», а не успешная проверка.

## Публикация и откат

Сейчас публикация отложена по поручению пользователя. После её разрешения создать или обновить `gh-pages` без force push, сохранив историю; перенести только содержимое проверенного `site/` в корень, добавить `.nojekyll`. Использовать штатную публикацию из ветки. Проверить итоговый URL, вложенные страницы, медиа, HTTPS, 404 и соответствие опубликованных файлов кандидату. Изменение DNS и подключение исходного домена сюда не входят.

До обновления существующей публикации сохранить SHA её предыдущего состояния; откат — обычный revert релизного коммита и повторная проверка деплоя. Для первой публикации прежнего сайта Pages нет: при необходимости отключить Pages. Исходную Joomla не удалять.
