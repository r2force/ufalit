# Сопровождение «Уфы литературной»

Исходники страниц и материалы находятся в `site/`, общие шаблоны — в `templates/`. Сборка и локальный предпросмотр описаны в [README.md](README.md). Внутренние ссылки и якоря должны работать под `/ufalit/`.

Перенос со старого сайта завершён. История работ и реестры исходных ссылок хранятся в `migration/`. Обращайтесь к архиву, когда для конкретной задачи нужно установить происхождение материала.

## Индекс кода

Если подключён MCP-сервер `codebase-memory`, используйте проект `ufalit` для поиска функций, структуры и связей. Перед работой с устаревшим индексом вызовите `index_repository` с абсолютным `repo_path` этого репозитория и `name: "ufalit"`; первичная установка и команды CLI описаны в [README.md](README.md#индекс-кода-для-ai-агентов). При отсутствии MCP используйте обычный поиск по файлам. Архив `migration/` и сторонние библиотеки исключены через `.cbmignore`: для них обращайтесь к файлам напрямую. Перед изменением найденного кода читайте его актуальный исходник.

## Работа с сайтом

- Для изменений оформления используйте семантический HTML, общий CSS и проектный skill `.agents/skills/frontend-design/SKILL.md`.
- При изменении вёрстки сохраняйте текст, авторство, подписи, порядок материалов и русские и башкирские символы. Разбиение длинной статьи на несколько URL согласуйте отдельно. Сохраняйте исходные сведения о правах и файл `LICENSE`.
- Перед коммитом проверьте ветку, remote и состав изменений. Берегите чужую работу. Force push запрещён.

## Общие компоненты и принцип DRY

- Поддерживайте список пунктов основного меню только в `templates/navigation.html`. Страница получает меню через `templates/header.html` и `scripts/render_site.py`. Относительные пути и `aria-current` вычисляет сборщик. Никогда не вставляйте копию меню в исходник страницы, в том числе при создании раздела по образцу существующего.
- В видеостраницах из `DEFERRED_PAGES` сохранились ручные копии меню. Не используйте эти страницы как шаблоны и не добавляйте подобных исключений. Образец для нового раздела — `site/pages/legends/index.html`: в исходнике описаны параметры страницы, материал и местное оглавление со ссылками на памятники. Такое оглавление относится к содержанию раздела.
- Применяйте DRY к разметке, CSS, скриптам и данным. Перед добавлением блока найдите, где уже реализована та же задача. Используйте существующий шаблон, класс, функцию или источник данных. Если нескольким страницам нужна одна реализация, вынесите её общую часть в одно место и передавайте различия параметрами.
- При проверке изменений ищите дубли в редактируемых исходниках. Повторение шапки в собранном HTML ожидаемо. Если поменяли общее меню, проверьте результат сборки на главной и вложенной странице: ссылки должны вести по правильным путям, а текущий пункт — соответствовать странице или разделу.

## Метки литературной карты

Главная использует [templates/atlas-places.json](templates/atlas-places.json) как единственный источник мест. Для добавления метки допишите объект в этот JSON-массив; для исправления существующей измените её объект. Не создавайте вторую копию массива мест в JS, HTML или `design_example/`: сборщик сам создаёт метки, список и начальную карточку. Порядок записей определяет порядок списка, первая запись открывается при загрузке. Массив должен оставаться непустым.

1. Найдите описание места в [site/pages/places/index.html](site/pages/places/index.html) и его HTML-якорь `id`. Если материала ещё нет, сначала добавьте его в подходящий раздел этой страницы с уникальным якорем и сохраните авторство, подписи и источники.
2. Возьмите существующую запись в `atlas-places.json` за образец. Укажите в `id` якорь нужного места: из него автоматически строится ссылка `pages/places/#<id>`. `id` должен быть уникален среди меток и существовать на странице памятных мест. Отдельное поле `url` здесь не задаёт адрес перехода — его формирует скрипт главной.
3. Проверьте координаты по карте или достоверному источнику именно для этого объекта. Порядок строго **`[долгота, широта]`**, например `[55.951599, 54.713468]` для дома-музея Аксакова. Если сервис показывает сначала широту, поменяйте числа местами. Запишите числа без кавычек; для улицы выбирайте её характерный участок. При исправлении привязки сохраните ссылку на источник в описании изменения или документации.
4. Используйте существующую фотографию в `site/assets/` или добавьте подходящий снимок с сохранением сведений о правах. В `image` укажите путь от корня сайта: `assets/places/aksakov/image003.jpg`, без `site/`, начального `/` и префикса `/ufalit/`. Эта фотография используется в метке, всплывающем окне, большой карточке и списке; проверьте её читаемость в круглом кадре и в карточке.

Поля записи:

| Поле | Что указывать |
| --- | --- |
| `id` | Уникальный якорь описания в `pages/places/`. |
| `label` | Короткое название для списка мест. |
| `title` | Полное название; также используется как описание фотографии в карточке. |
| `writer` | Имя связанного с местом писателя; участвует в поиске. |
| `category` | Подпись типа места по-русски, например `Дом-музей`. |
| `categories` | Массив служебных категорий для фильтров, например `["museum"]`; не путать с русской подписью `category`. |
| `address` | Подтверждённый адрес или местоположение. |
| `coordinates` | Два числа: `[долгота, широта]`. |
| `image` | Путь к существующей фотографии от корня сайта. |
| `paragraphs` | Непустой массив абзацев обычного текста из материала о месте. Первый абзац показывается во всплывающем окне, все — в большой карточке. |
| `quote` | Необязательная цитата с точным текстом и атрибуцией из источника. Если цитаты нет, поле пропустите. |

Действующие категории и кнопки фильтров:

| `categories` | Фильтр |
| --- | --- |
| `["museum"]` | Дома-музеи |
| `["park"]` | Сады и парки |
| `["theatre"]` или `["library"]` | Культура |
| `["street"]` | Улицы |

Для обычного добавления места используйте существующую категорию. Новый тип потребует согласованного изменения массива `filters` в [site/assets/ufalit-map.js](site/assets/ufalit-map.js), кнопок в [templates/atlas.html](templates/atlas.html) и проверок фильтрации в [scripts/test_home_map.js](scripts/test_home_map.js). Неизвестная категория будет видна в «Все места», но не попадёт в существующие тематические фильтры.

После изменения данных:

- Если изменился набор мест, обновите ожидаемые ID и количества результатов в `scripts/test_home_map.js`. Сохраните проверки ссылок, изображений, поиска, фильтров и пустого результата; для места за пределами проверяемой области расширьте географическую проверку по подтверждённой привязке.
- При изменении количества мест проверьте мобильный список `.atlas-choices` в [site/assets/atlas.css](site/assets/atlas.css): сейчас число колонок задано как `repeat(6, 12rem)` и не вычисляется из JSON.
- Выполните `node scripts/test_home_map.js`, затем соберите предпросмотр по инструкции в `README.md`. Используйте `--output` с новым каталогом; `--in-place` предназначен для одноразового CI checkout.
- В браузере проверьте новую метку и выбор из списка, фотографии на карте и в карточке, переход к правильному якорю, поиск по названию/писателю/адресу, соответствующий фильтр и сброс. Проверьте мобильную версию и кнопку «Все места на карте»: она должна вмещать видимые точки, а отдаление — останавливаться на этом масштабе. Предел отдаления пересчитывается автоматически; фиксированный `minZoom` для нового места не подставляйте.
- Если менялись JS или CSS, обновите соответствующие версии `?v=` в подключениях. Для изменения только `atlas-places.json` это не требуется: данные встраиваются в HTML при сборке.

## Оформление материалов

Для выделенных цитат используйте семантический `<blockquote>` и общий стиль `.museum blockquote:not(.poem)` в `site/assets/museum.css`: светлый фон, скругление, бордовая полоса слева, курсив Literata и достаточно воздуха, как в примере `design_example`. Текст и атрибуцию сохраняйте точно; не превращайте обычные абзацы в цитаты и не выдумывайте автора. Тёмный эпиграф главной `.poem` остаётся отдельным компонентом. Для новых вариантов проверяйте контраст, адаптивность и темы чтения.

- **Стихи.** В читальном зале используйте общий стиль `.reader-verse` из `site/assets/reader.css`. Сохраняйте авторские переносы строк, границы строф, посвящения и подпись переводчика. На узком экране длинная строка должна помещаться за счёт мягкого переноса.
- **Статьи.** Используйте семантический `<article>`, последовательные уровни заголовков и общую типографику чтения. Для длинной прозы ориентируйтесь на колонку в 60–80 знаков и различимые интервалы между абзацами. Сохраняйте списки, библиографию и связь иллюстраций с текстом.
- **Фотографии и иллюстрации.** Связывайте снимок и исходную подпись через `<figure>` и `<figcaption>`. Для фотографий в галерее используйте `templates/photo.html`. Сохраняйте пропорции, авторство и доступ к полному кадру. Для содержательного изображения задавайте осмысленный `alt` с учётом соседней подписи.
- **Аудио, видео и документы.** Оформляйте однотипные материалы единообразно: название и исходная подпись рядом с записью, формат файла рядом со ссылкой на скачивание. Используйте общие стили подписей и ссылок. При добавлении варианта оформления проверяйте читаемость на узком экране и в поддерживаемых темах чтения.

## Репозиторий и публикация

Пользователь поручил отправлять завершённые и проверенные изменения в `origin/main` по умолчанию. Перед итоговым ответом закоммитить только файлы текущей задачи, выполнить `git push origin main` и проверить, что коммит появился на GitHub. Если пользователь указал другую ветку или попросил оставить результат локально, следовать его указанию. В итоговом ответе дать ссылку на отправленный коммит.

GitHub Pages публикует собранный каталог `site/` через `.github/workflows/pages.yml`. Настройки Pages, DNS и CNAME меняйте только по отдельному поручению.
