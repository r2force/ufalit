# Сопровождение «Уфы литературной»

Исходники страниц и материалы находятся в `site/`, общие шаблоны — в `templates/`. Сборка и локальный предпросмотр описаны в [README.md](README.md). Внутренние ссылки и якоря должны работать под `/ufalit/`.

Перенос со старого сайта завершён. История работ и реестры исходных ссылок хранятся в `migration/`. Обращайтесь к архиву, когда для конкретной задачи нужно установить происхождение материала.

Актуальное поведение определяют исходники, шаблоны и действующие проверки. Планы и QA в `migration/` описывают датированные срезы: не восстанавливайте удалённые владельцем материалы по старому плану. Сводка сверки планов с текущей реализацией — [migration/STATUS.md](migration/STATUS.md).

## Индекс кода

Любой агент может создать индекс командой `python3 scripts/code_index.py setup` и обновить его командой `python3 scripts/code_index.py index`; установленный агент или MCP-клиент для этого не нужен. Для поиска функций, структуры и связей используйте CLI из [README.md](README.md#индекс-кода-для-ai-агентов) или MCP-сервер `codebase-memory` с проектом `ufalit`. Через MCP обновляйте индекс вызовом `index_repository` с абсолютным `repo_path` этого репозитория и `name: "ufalit"`. Архив `migration/` и сторонние библиотеки исключены через `.cbmignore`: для них обращайтесь к файлам напрямую. Перед изменением найденного кода читайте его актуальный исходник.

## Работа с сайтом

- Для изменений оформления используйте семантический HTML, общий CSS и проектный skill `.agents/skills/frontend-design/SKILL.md`.
- При изменении вёрстки сохраняйте текст, авторство, подписи, порядок материалов и русские и башкирские символы. Разбиение длинной статьи на несколько URL согласуйте отдельно. Сохраняйте исходные сведения о правах и файл `LICENSE`.
- Перед коммитом проверьте ветку, remote и состав изменений. Берегите чужую работу. Force push запрещён.

## Общие компоненты и принцип DRY

- Поддерживайте список пунктов основного меню только в `templates/navigation.html`. Страница получает меню через `templates/header.html` и `scripts/render_site.py`. Относительные пути и `aria-current` вычисляет сборщик. Никогда не вставляйте копию меню в исходник страницы, в том числе при создании раздела по образцу существующего.
- Все страницы, включая видео и легенды, используют общий каркас; исключений `DEFERRED_PAGES` больше нет. Образец для нового раздела — `site/pages/legends/index.html`: в исходнике описаны параметры страницы, материал и местное оглавление со ссылками на памятники. Такое оглавление относится к содержанию раздела.
- Применяйте DRY к разметке, CSS, скриптам и данным. Перед добавлением блока найдите, где уже реализована та же задача. Используйте существующий шаблон, класс, функцию или источник данных. Если нескольким страницам нужна одна реализация, вынесите её общую часть в одно место и передавайте различия параметрами.
- При проверке изменений ищите дубли в редактируемых исходниках. Повторение шапки в собранном HTML ожидаемо. Если поменяли общее меню, проверьте результат сборки на главной и вложенной странице: ссылки должны вести по правильным путям, а текущий пункт — соответствовать странице или разделу.

## Метки литературной карты

Отдельная страница [site/pages/map/index.html](site/pages/map/index.html) использует [templates/atlas-places.json](templates/atlas-places.json) как единственный источник мест. На главной находится статья о проекте и навигация по разделам. Для добавления метки допишите объект в этот JSON-массив; для исправления существующей измените её объект. Не создавайте вторую копию массива мест в JS, HTML или `design_example/`: сборщик сам создаёт метки, список и начальную карточку. Порядок записей определяет порядок списка, первая запись открывается при загрузке. Массив должен оставаться непустым.

1. Найдите описание места и его HTML-якорь `id` на странице, где материал раскрыт: обычно в [site/pages/places/index.html](site/pages/places/index.html), а для памятников из раздела «Легенды» — в [site/pages/legends/index.html](site/pages/legends/index.html). Если материала ещё нет, сначала добавьте его в подходящий раздел с уникальным якорем и сохраните авторство, подписи и источники.
2. Возьмите существующую запись в `atlas-places.json` за образец. `id` должен быть уникальным идентификатором метки. Для материала в `pages/places/` он обычно совпадает с якорем, и ссылка строится как `pages/places/#<id>`. Если подробный материал находится на другой странице, укажите `detail_url` — например, `pages/legends/#zuhra`; эта ссылка используется в списке и карточке карты.
3. Проверьте координаты по карте или достоверному источнику именно для этого объекта. Порядок строго **`[долгота, широта]`**, например `[55.951599, 54.713468]` для дома-музея Аксакова. Если сервис показывает сначала широту, поменяйте числа местами. Запишите числа без кавычек; для улицы выбирайте её характерный участок. При исправлении привязки сохраните ссылку на источник в описании изменения или документации.
4. Используйте существующую фотографию в `site/assets/` или добавьте подходящий снимок с сохранением сведений о правах. В `image` укажите путь от корня сайта: `assets/places/aksakov/image003.jpg`, без `site/`, начального `/` и префикса `/ufalit/`. Эта фотография используется в метке, всплывающем окне, большой карточке и списке; проверьте её читаемость в круглом кадре и в карточке.

Поля записи:

| Поле | Что указывать |
| --- | --- |
| `id` | Уникальный идентификатор метки; для материала в `pages/places/` обычно равен HTML-якорю. |
| `detail_url` | Необязательный путь к подробному материалу и якорю от корня сайта. По умолчанию — `pages/places/#<id>`; задайте, если материал раскрыт на другой странице. |
| `label` | Короткое название для списка мест. |
| `title` | Полное название; также используется как описание фотографии в карточке. |
| `writer` | Имя связанного с местом писателя; участвует в поиске. |
| `category` | Подпись типа места по-русски, например `Дом-музей`. |
| `categories` | Массив служебных категорий для фильтров, например `["museum"]`; не путать с русской подписью `category`. |
| `address` | Подтверждённый адрес или местоположение. |
| `coordinates` | Два числа: `[долгота, широта]`. |
| `image` | Путь к существующей фотографии от корня сайта. |
| `paragraphs` | Непустой массив абзацев обычного текста из материала о месте. Первый абзац показывается во всплывающем окне, все — в большой карточке. |
| `quote` | Необязательная цитата с точным текстом и атрибуцией из источника. Если цитаты нет, поле пропустите. |

Действующие категории и кнопки фильтров:

| `categories` | Фильтр |
| --- | --- |
| `["museum"]` | Дома-музеи |
| `["monument"]` | Памятники |
| `["park"]` | Сады и парки |
| `["theatre"]` или `["library"]` | Культура |
| `["building"]` | Здания |
| `["street"]` | Улицы |

Если место не относится ни к одной категории (например, кладбище), массив `categories` можно не указывать: метка будет видна только в «Все места».

Для обычного добавления места используйте существующую категорию. Новый тип потребует согласованного изменения массива `filters` в [site/assets/ufalit-map.js](site/assets/ufalit-map.js), кнопок в [templates/atlas.html](templates/atlas.html) и проверок фильтрации в [scripts/test_home_map.js](scripts/test_home_map.js). Неизвестная категория будет видна в «Все места», но не попадёт в существующие тематические фильтры.

После изменения данных:

- Если изменился набор мест, обновите ожидаемые ID и количества результатов в `scripts/test_home_map.js`. Сохраните проверки ссылок, изображений, поиска, фильтров и пустого результата; для места за пределами проверяемой области расширьте географическую проверку по подтверждённой привязке.
- При изменении количества мест проверьте список `.atlas-choices` в [site/assets/atlas.css](site/assets/atlas.css): на большом экране он содержит три столбца, на среднем — два; на телефоне выкладывается тремя рядами по горизонтали (`grid-template-rows: repeat(3, auto)`, `grid-auto-columns: 12rem`). Сверяйте правила адаптивности с текущим CSS.
- Выполните `node scripts/test_home_map.js`, затем соберите предпросмотр по инструкции в `README.md`. Используйте `--output` с новым каталогом; `--in-place` предназначен для одноразового CI checkout.
- `selectMarker` в [site/assets/map-widget.js](site/assets/map-widget.js) принимает `zoom`: страница карты передаёт `focusZoom()` из [site/assets/ufalit-map.js](site/assets/ufalit-map.js), чтобы выбор из списка приближал к метке до масштабной линейки 50 м. При `popupOnMarkerClick: false` окно к метке не привязывается и клик показывает описание только в панели справа — не возвращайте `setPopup` безусловно.
- В браузере проверьте новую метку и выбор из списка, фотографии на карте и в карточке, переход к правильному якорю, поиск по названию/писателю/адресу, соответствующий фильтр и сброс. Проверьте мобильную версию и кнопку «Все места на карте»: она должна вмещать видимые точки, а отдаление — останавливаться на этом масштабе. Предел отдаления пересчитывается автоматически; фиксированный `minZoom` для нового места не подставляйте.
- Если менялись JS или CSS, обновите соответствующие версии `?v=` в подключениях. Для изменения только `atlas-places.json` это не требуется: данные встраиваются в HTML при сборке.

## Дизайнерские предпочтения текущего сайта

Ориентир — литературный атлас и музейный путеводитель: тёплая бумага, архивные фотографии, книжная типографика, спокойный интерфейс. При сопровождении продолжайте существующий дизайн. Макеты `design_example/` помогают понять замысел, но текущие шаблоны и итоговые правила CSS имеют приоритет: поздние правила в `museum.css` уточняют ранние. Общие советы skill о поиске новой эстетики не требуют менять утверждённую палитру или добавлять новый первый экран.

| Токен в `site/assets/museum.css` | Значение и роль |
| --- | --- |
| `--paper` / `--paper-card` | `#F6F3EC` / `#FCFAF5`: фон бумаги и светлое паспарту. |
| `--ink` / `--ink-muted` | `#142829` / `#465959`: основной и второстепенный текст, тёмные музейные поверхности. |
| `--accent` | `#245D60`: ссылки и спокойные акценты интерфейса. |
| `--wine` | `#8E2D36`: выбранное состояние и основные действия. |
| `--bronze` / `--line` | `#B58347` / `#D6CFC1`: ограда эпиграфа, рамки экспонатов и разделители. |

- Заголовки — локальный **Cormorant Garamond**, основной книжный текст — **Literata**, интерфейс — **Inter**. **JetBrains Mono** оставляйте для архивных метаданных и годов, как в галерее. Шрифты и лицензии находятся в `site/assets/fonts/`; не добавляйте внешнюю загрузку шрифтов. Используйте существующие переменные `--display`, `--reading`, `--ui`, `--mono`.
- Общая ширина `.wrap` — до `78rem`; длинный текст внутри обычно ограничен `70–76ch`, интерлиньяж — около `1.75–1.78`. Главная статья о проекте намеренно занимает ширину первого экрана, а `.reader-body` на главной не сужается до книжной колонки. Сохраняйте это исключение.
- На главной оставляйте двухчастный первый экран с эпиграфом Назара Наджми и бронзовым мотивом ограды. Логотип — книга с меткой карты из `site/assets/ufalit-logo.svg`; продолжайте существующую векторную систему.
- Навигация по разделам в статье главной — компактные строки с иконкой, названием и описанием, по две в ряд и по одной на телефоне. Дополнительные бейджи и действия в шапке легенд убраны; не возвращайте их по старым макетам.
- Галерея — светлое паспарту с сохранением полного кадра, сетка карточек литераторов 3 → 2 → 1, четыре архивные раскладки и общий просмотр оригинала. Видеокопилка — банки с портретными этикетками и один нативный плеер на подборку. Легенды — иллюстрированные главы с оглавлением памятников, а не обязательная карусель из 29 слайдов.
- Скругления, рамки и тени выбирайте по соседнему компоненту: их величины различаются по назначению. Не превращайте каждый абзац в карточку; не добавляйте декоративные градиенты, новые шрифты, служебные подписи и анимации без задачи. Существующий малахитовый градиент первого экрана сохраняйте.
- Цвета чтения задавайте через переменные темы: бумага, сепия и ночь. Новые элементы должны оставаться читаемыми во всех трёх темах. Сохраняйте видимый `:focus-visible`, семантические кнопки, управление клавиатурой и `prefers-reduced-motion`.
- При изменениях вёрстки проверяйте собранный сайт под `/ufalit/` на 320, 768 и 1440 px, увеличение текста до 200% и доступность основного материала без JavaScript. Содержательные тексты, подписи и авторство не меняйте ради макета.

## Защита почтовых ссылок

В исходниках пишите обычный `<a href="mailto:…">`: сборщик автоматически заменяет его доступной кнопкой, кодирует адрес и параметры письма и подключает `ufalit-contact.js` только там, где есть контакт. Полный адрес не должен появляться в подписи, `title`, `aria-label`, открытом `data-*` или индексе поиска опубликованной страницы; это проверяют `scripts/test_email_contacts.py` и `scripts/test_email_contacts.js`. Не восстанавливайте все `mailto` при загрузке: адрес декодируется только по нажатию. Без JS выводится пояснение. Это обфускация от простых сборщиков, а не гарантия против ботов с браузером; открытый Git-репозиторий не скрывает исходники. В текущем контенте почтовых ссылок нет — не добавляйте выдуманный адрес.

## Проверки текущей реализации

Команды проверки перечислены в [README.md](README.md#проверки). Карта проверяется исторически названным `test_home_map.js`, хотя расположена на отдельной странице. Поиск `ufalit-search.js` индексирует только произведения текущего читального зала; не называйте его общесайтовым. Видеокаталог поддерживает пустые коллекции; удалённые владельцем аудио, ролики и презентации не восстанавливайте для выполнения старого плана. Для обычных изменений запускайте относящиеся к ним проверки; при изменении сборщика — весь набор и сборку в новый каталог.

## Оформление материалов

Для выделенных цитат используйте семантический `<blockquote>` и общий стиль `.museum blockquote:not(.poem)` в `site/assets/museum.css`: светлый фон, скругление, бордовая полоса слева, курсив Literata и достаточно воздуха, как в примере `design_example`. Текст и атрибуцию сохраняйте точно; не превращайте обычные абзацы в цитаты и не выдумывайте автора. Тёмный эпиграф главной `.poem` остаётся отдельным компонентом. Для новых вариантов проверяйте контраст, адаптивность и темы чтения.

- **Стихи.** В читальном зале используйте общий стиль `.reader-verse` из `site/assets/reader.css`. Сохраняйте авторские переносы строк, границы строф, посвящения и подпись переводчика. На узком экране длинная строка должна помещаться за счёт мягкого переноса.
- **Статьи.** Используйте семантический `<article>`, последовательные уровни заголовков и общую типографику чтения. Для длинной прозы ориентируйтесь на колонку в 60–80 знаков и различимые интервалы между абзацами. Сохраняйте списки, библиографию и связь иллюстраций с текстом.
- **Фотографии и иллюстрации.** Связывайте снимок и исходную подпись через `<figure>` и `<figcaption>`. Для фотографий в галерее используйте `templates/photo.html`. Сохраняйте пропорции, авторство и доступ к полному кадру. Для содержательного изображения задавайте осмысленный `alt` с учётом соседней подписи.
- **Аудио, видео и документы.** Оформляйте однотипные материалы единообразно: название и исходная подпись рядом с записью, формат файла рядом со ссылкой на скачивание. Используйте общие стили подписей и ссылок. При добавлении варианта оформления проверяйте читаемость на узком экране и в поддерживаемых темах чтения.

## Репозиторий и публикация

Пользователь поручил отправлять завершённые и проверенные изменения в `origin/main` по умолчанию. Перед итоговым ответом закоммитить только файлы текущей задачи, выполнить `git push origin main` и проверить, что коммит появился на GitHub. Если пользователь указал другую ветку или попросил оставить результат локально, следовать его указанию. В итоговом ответе дать ссылку на отправленный коммит.

GitHub Pages публикует собранный каталог `site/` через `.github/workflows/pages.yml`. Настройки Pages, DNS и CNAME меняйте только по отдельному поручению.
